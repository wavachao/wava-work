# UI工作流
- 检查现有设计系统、参考与真实内容，明确受众、主要操作、层级和设备。无参考时选明确视觉方向，简短说明后实施。
- 读取偏好模块。展示可有个性、意境和动态；工具优先操作效率，不默认渐变背景、宣传大标题、三列卡片和装饰图标。
- 内容决定布局，允许不同密度；统一字体、间距、对齐、色彩和状态，不编造评价、人数或功能。
- 复用组件与原生控件；ponytail优化实现，不削减要求的品质和交互。
- 覆盖相关loading/empty/error/success状态，不为无关场景造框架。
- 检查适用的响应式、语义、键盘操作、可见焦点、标签和替代文本。按WCAG 2.2 AA相关要求：普通文字对比度通常至少4.5:1，大字3:1，不只靠颜色传达含义。
- 动效服务反馈或叙事，尊重prefers-reduced-motion，不遮挡操作或无意义循环。
- 实际验证主要用户路径、适用宽窄屏、溢出和浏览器错误；有浏览器能力时交互并检查截图，能力不足如实说明。
- 生成图像用于素材，数据图/精确结构用可控工具；已有SVG和组件优先直接编辑。
- 分别验收功能、视觉、可访问性；截图不能证明功能通过。
